       - `tl.static_assert(not IS_COMPLEX, "complex64 lands in 07-02 (D-41a pre-wiring)")` — the gate. Plan 07-02 removes ONLY this single line.
       - `row_id = tl.program_id(axis=0)` — selects the column tile within a row (n_row_tiles axis)
       - `bn_id = tl.program_id(axis=1)` — selects the (batch, nstack) row
       - Compute the (batch, nstack) decomposition: `nstack_idx = bn_id % nstacks`, `batch_idx = bn_id // nstacks` (or vice-versa; planner picks based on memory-coalescing preference — recommend `batch_idx = bn_id // nstacks, nstack_idx = bn_id % nstacks` so consecutive bn_id values share twiddle).
       - `tile_offsets = tl.arange(0, TILE_N)` — the in-register tile indices.
       - Compute the absolute column offsets inside the row: `col_start = row_id * TILE_N`, `pos = col_start + tile_offsets`.
       - Load the input tile: `row_base = (batch_idx * nstacks + nstack_idx) * n` — for the real path; complex path doubles (gated off in Plan 07-01).
       - `x = tl.load(input_ptr + row_base + pos)` — full-tile load (no mask needed because TILE_N divides n by construction — the wrapper guarantees `n_row_tiles = n // TILE_N` is an integer).
       - Unrolled 3-stage butterfly via `for stage_offset in tl.static_range(STAGE_COUNT)`:
         - Compute the per-stage `log_stride`: if INCREASING_STRIDE: `log_stride = STAGE_START + stage_offset`; else: `log_stride = LOG_N - 1 - (STAGE_START + stage_offset)`.
         - `stride = 1 << log_stride` — the partner-swap distance within the in-register tile (always strictly less than TILE_N by construction of TILE_N = 1 << (max(group_stages) + 1)).
         - Load the 4 twiddle entries `(0,0), (0,1), (1,0), (1,1)` for the current stage. The twiddle index is `twiddle[nstack_idx, block_idx, idx_in_block, pair_idx, ...]` where `idx_in_block = STAGE_START + stage_offset` and `pair_idx` ranges over `n // (2 * stride)`. The kernel loads via pointer arithmetic on `twiddle_ptr` with the layout `(nstacks, nblocks, log_n, n // 2, 2, 2)` (row-major last-dim-fastest). Inside a tile of width `TILE_N`, each program needs `TILE_N // 2` pairs of twiddle entries per stage; load these with `tl.load(twiddle_ptr + ...)`.
         - Compute the partner indices via `pair_mask = (tile_offsets & stride) == 0` — True on the "lower" element of each pair.
         - For each (lower, upper) pair, compute the new values via the 2x2 multiply: if the original `_torch_ref` computes `(t * output_reshape).sum(dim=4)` with `t` of shape `(2, 2)` and `output_reshape` of shape `(1, 2, stride)`, the in-register form is: `lower_new = t_00 * lower + t_01 * upper`, `upper_new = t_10 * lower + t_11 * upper`. Use `tl.where(pair_mask, lower_new, upper_new)` to write back into the same `x` register tile.
       - `tl.store(output_ptr + row_base + pos, x)` — single store at the end (per D-40b "no shared memory needed at the 3-stage cap").
