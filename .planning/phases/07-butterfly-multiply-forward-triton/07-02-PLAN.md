**Phase 4 4-FMA template (`04-COMPLEX-LAYOUT.md:58-76`)** — VERBATIM:

```
@triton.jit
def butterfly_kernel(in_ptr, twiddle_ptr, out_ptr, ...,
                     IS_COMPLEX: tl.constexpr, BLOCK_SIZE: tl.constexpr):
    # ... load layout for real-or-complex inputs ...
    if IS_COMPLEX:
        # Load (re, im) pairs for input and twiddle
        a_re, a_im = tl.load(in_ptr + off_re), tl.load(in_ptr + off_im)
        c_re, c_im = tl.load(twiddle_ptr + t_re), tl.load(twiddle_ptr + t_im)
        # Complex multiply (a + bi)(c + di) = (ac - bd) + (ad + bc)i — 4 FMAs
        out_re = a_re * c_re - a_im * c_im
        out_im = a_re * c_im + a_im * c_re
        tl.store(out_ptr + off_re, out_re)
        tl.store(out_ptr + off_im, out_im)
    else:
        a = tl.load(in_ptr + off)
        c = tl.load(twiddle_ptr + t)
        tl.store(out_ptr + off, a * c)
```

**For butterfly's per-pair multiply** (the math is more involved than diag_mult's pointwise multiply): each butterfly stage computes the 2×2 matrix-vector product `[[t_00, t_01], [t_10, t_11]] @ [lower, upper]`. The real-only path uses `lower_new = t_00 * lower + t_01 * upper; upper_new = t_10 * lower + t_11 * upper`. The complex64 path applies the 4-FMA to each of the four scalar multiplies AND each of the two adds. Per `04-COMPLEX-LAYOUT.md:69-71`:
- `lower_new_re = (t_00_re * lower_re - t_00_im * lower_im) + (t_01_re * upper_re - t_01_im * upper_im)`
- `lower_new_im = (t_00_re * lower_im + t_00_im * lower_re) + (t_01_re * upper_im + t_01_im * upper_re)`
- `upper_new_re = (t_10_re * lower_re - t_10_im * lower_im) + (t_11_re * upper_re - t_11_im * upper_im)`
- `upper_new_im = (t_10_re * lower_im + t_10_im * lower_re) + (t_11_re * upper_im + t_11_im * upper_re)`

In the kernel's register-resident tile (per Plan 07-01's D-40b), the in-register vector `x` holds `TILE_N` real elements per tile when IS_COMPLEX=False. When IS_COMPLEX=True (view_as_real layout), the in-register vector holds `2 * TILE_N` real elements per tile — even-indexed elements are real parts, odd-indexed elements are imaginary parts. The 4-FMA branch loads `x_re` (even positions) and `x_im` (odd positions) separately and applies the formulas above; final store interleaves them back.

**The PITFALLS §1 unitary detector (the load-bearing complex correctness gate)** — at `.planning/research/PITFALLS.md` §1: "The cheapest correctness detector for the complex code path is the unitary butterfly identity `U U^* = I`.
