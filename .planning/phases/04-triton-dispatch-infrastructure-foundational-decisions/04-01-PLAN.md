<objective>
Lay down the dispatch infrastructure foundation that every subsequent Phase 5-10 kernel port inherits: create the `_torch_ref/` peer package (moving `butterfly_multiply_torch` into it with a back-compat shim at the old location), create the `_cuda_legacy/` minimal wrapper that re-exposes the already-loaded `torch.ops.torch_structured.butterfly_multiply`, create the `torch_structured/_ops.py` single dispatch module with the `_resolve` + `set_backend` API (mutating module-level callables per D-05's call-site contract), bump the PyTorch floor to `torch>=2.6` in `pyproject.toml`, expose `set_backend` at the top level, and produce two companion docs (`04-COMPLEX-LAYOUT.md` per D-02 and `04-DEPRECATION-PLAN.md` per D-15) that Phase 7 and Phase 10 will implement verbatim.

Purpose: Lock in the structural shape every later phase reads from. Without this plan, Plan 04-02 has no `_ops.py` to add the demonstrator op into and no `set_backend` for the test fixture to drive. Phases 5-8 have no `_torch_ref/` to hold their reference impls against, no `_cuda_legacy/` to fall back to, no complex64 layout doc to consume, and no deprecation-warning template for Phase 10.

Output: 4 new Python packages/modules under `torch_structured/`, 1 modified shim, 1 modified top-level package init, 1 modified `pyproject.toml`, and 2 phase-companion markdown docs. No Triton kernels yet (demonstrator lands in Plan 04-02).
