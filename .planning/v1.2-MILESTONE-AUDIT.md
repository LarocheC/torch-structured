## Discovered defects (non-blocking)

### 1. `DEPR-02` — DeprecationWarning leaks onto the default Triton path  *(low)*
`torch_structured/_ops.py:329-332` imports `_cuda_legacy` to build the routing-fallback closure without a `catch_warnings()` wrap, so a bare `import torch_structured` on the **default** backend emits the CUDA `DeprecationWarning` whenever a CUDA build is present — even though the user never selected `cuda`. Contradicts the D-74b intent (warning reserved for explicit `set_backend('cuda')`). The per-op probes were wrapped; this routing-closure import was missed. **Fix:** one `warnings.catch_warnings()` wrap.

### 2. `TEST-01/02/03` — 3-axis agreement gate not clean on full-3-axis hardware  *(medium)*
The conftest `backend` fixture parametrizes `{torch, triton, cuda}`. On the dev host the `cuda` axis was *always skipped* (CUDA-version mismatch), so prior "all green" claims never exercised it. With this session's matched CUDA build, **23 cuda-axis tests fail** (torch+triton remain 100% green, 122 passed) in `test_diag_mult.py`, `test_hadamard_triton.py`, `test_butterfly_triton.py`. Two causes, both test-side (the CUDA kernels are numerically correct):
- **Tolerance gap:** per-op suites use `atol=1e-6`, below the fp32 accumulation noise floor (~2.3e-5 abs ≈ 1.4e-7 rel). `test_phase9_integration.py` already widened to `1e-5` for `log_n>=8`; the per-op suites did not.
- **Missing fp64 cuda skip:** fp64 gradcheck tests skip the `triton` param (Triton fp32-only) but not the `cuda` param (legacy CUDA is *also* fp32-only) → `"…_cuda" not implemented for 'Double'`.

**Fix:** mirror the `1e-5` widening + add a cuda-param fp64 skip-gate.
