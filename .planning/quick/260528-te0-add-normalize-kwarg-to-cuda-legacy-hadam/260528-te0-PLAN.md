<objective>
Add a `normalize: bool = False` keyword argument to `torch_structured/_cuda_legacy/hadamard.py::hadamard_transform`, bringing its signature into parity with the `_torch_ref` and `_triton` backends. The three backends are bound under the same name `hadamard_transform` by the `_ops.py` resolver, so consumers (and the backend-agreement tests) call them interchangeably with `normalize=...`. The CUDA legacy wrapper currently lacks the parameter, so the now-live `[cuda-*]` test parametrizations raise `TypeError: hadamard_transform() got an unexpected keyword argument 'normalize'`.

The raw pybind op returns the UNNORMALIZED FWHT, so the `normalize=True` division by `2**(m/2)` must be applied in Python in the wrapper (verified empirically: `H @ [1,0,0,0] = [1,1,1,1]`).

Purpose: Restore backend interchangeability now that the CUDA path is live (CUDA 13.0 rebuild matched the host).
Output: A single-function edit to `_cuda_legacy/hadamard.py`.
</objective>
