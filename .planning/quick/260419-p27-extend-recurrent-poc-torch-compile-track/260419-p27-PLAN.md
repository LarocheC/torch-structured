<objective>
Extend the existing recurrent_poc benchmark suite in two orthogonal concerns:
Track A adds a `--compile` path to the StackedGateGRUCell benchmark that wraps the
whole unrolled time-loop with `torch.compile`, records per-combo failures
gracefully, and reports a new `compile_fwd_bwd_ms` column. Track B replaces
LinearDiagRNN's hard-coded dense B and C linears with `make_linear`-driven
structured projections and extends its benchmark CLI to sweep over kinds
(symmetric via `--kinds` or asymmetric via `--kind-B`/`--kind-C`) while skipping
shape-incompatible combos rather than crashing.

Purpose: measure the actual win from compiling the whole unroll (not the cell)
and compare structured B/C in a linear RNN the same way we compared them in the
nonlinear GRU, all within the existing POC suite (no new files if avoidable).

Output: modified experiments/recurrent_poc/{gru,bench_gru,lin_rnn,bench_lin_rnn}.py
with the new behavior, each file under ~180 LOC, sanity-checked on the sm_89
RTX 4090 venv.

Goal: add torch.compile support to bench_gru.py that wraps the ENTIRE unrolled
time-loop as one compiled function (not the per-step cell — reduce-overhead
CUDA graphs only pay off when the recorded region spans many steps). The existing
code wraps the cell instead, which is the anti-pattern we're replacing.

Step 1 — gru.py: add a module-level helper `unroll_cell(cell, x_seq, h0) -> h_seq`
right below the StackedGateGRUCell class. Signature: takes `cell` (nn.Module with
forward(x_t, h_prev)), `x_seq` of shape (B, T, input_size), and `h0` of shape
(B, hidden_size). Loops t in range(x_seq.size(1)), updates h = cell(x_seq[:, t], h),
and returns torch.stack(outs, dim=1) of shape (B, T, hidden_size). Returning the
full stacked sequence (not just final h) is important: torch.compile needs a
concrete return value to trace, and benching fwd+bwd needs a scalar to .sum().
Keep the helper plain Python (no @torch.compile decoration — compile is applied
at the call site in bench_gru.py).

Step 2 — bench_gru.py: rewrite `bench_one` and `main` to:

(a) Remove the current `run_cell` helper (it returned only final h) and the
    existing `compile_cell` branch that wrapped the cell. Import `unroll_cell`
    from experiments.recurrent_poc.gru.

(b) Add dynamo log suppression at the top of main() (after args parsing, only
    when args.compile):
        import torch._dynamo
        torch._dynamo.config.suppress_errors = True
        os.environ.setdefault("TORCH_LOGS", "")

(c) Change `bench_one` signature to accept `compile_mode: str | None` instead
    of bool `compile_cell`. When None (i.e. --compile not passed), skip the
    compile branch entirely and return t_compile_fwd_bwd_ms = None.

(d) For the compile branch (only when compile_mode is not None):
      - Build a fresh StackedGateGRUCell (same kind/H/T) — do NOT reuse the
        eager model; a second model keeps the eager vs compiled timing clean.
      - Wrap the unroll: `compiled_unroll = torch.compile(unroll_cell, mode=compile_mode, fullgraph=False)`
      - Define `compile_fwd_bwd()` that zero-grads the fresh cell, calls
        `compiled_unroll(cell, x, h0).sum().backward()`.
      - Try it with compile_mode="reduce-overhead" first. On any exception
        (RuntimeError, AssertionError, ValueError, torch._dynamo exceptions,
        or any other Exception subclass — catch bare Exception here because
        dynamo errors are varied), try ONCE more with compile_mode="default".
        If that also fails, record status "compile_fail" with reason set to
        str(e)[:80] and a prefix indicating the fallback was attempted.
      - For the successful mode: use warmup=max(args.warmup, 5) and the
        existing iters (first compile pass is slow; bump warmup only for the
        compile measurement, leave eager measurement untouched). Use the
        existing time_fn helper.

(e) Extend the result dict to carry a "compile_status" ("ok"|"compile_fail"|
    "not_requested") and a "t_compile_fwd_bwd_ms" (float or None).

(f) Rewrite `_row_cells` and `_print_table` so the "compile_fwd_bwd_ms" column
    appears only when args.compile was passed. Pass `show_compile: bool` down
    from main() into the printer. When shown, ok rows print the float with
    3 decimals; compile_fail rows print `compile_fail: <reason>` (ellipsized
    to ~50 chars inside the cell to keep table width sane); not_requested
    rows are unreachable when show_compile is True.

(g) Update the --compile argparse help to say: "Additionally bench torch.compile
    on the whole unroll loop. Uses warmup=max(warmup, 5) for the compile
    measurement because the first pass is slow. Per-combo failures are recorded
    as compile_fail and do not abort the sweep."

(h) Keep existing columns (kind, H, T, params, fwd_ms, fwd_bwd_ms). Do NOT
    remove them. The compile column is strictly additive.

(i) Keep the existing cudnn branch exactly as-is — cudnn ignores --compile
    (report "-" in the compile column for cudnn rows so the table stays
    rectangular; add a one-line comment explaining why).

(j) Stay under ~180 LOC in bench_gru.py after the rewrite. If it gets close,
    inline _row_cells into _print_table to save lines.
