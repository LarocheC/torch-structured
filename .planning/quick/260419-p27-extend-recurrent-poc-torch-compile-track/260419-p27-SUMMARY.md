# 260419-p27 Quick Task Summary: Extend recurrent_poc for torch.compile + structured B/C

## One-liner

Added `--compile` to `bench_gru.py` that wraps the full unroll loop (not the per-step cell) with `torch.compile`, gracefully degrading on graph breaks, and extended `bench_lin_rnn.py` to sweep structured B/C projections (symmetric via `--kinds`, asymmetric via `--kind-B`/`--kind-C`) with circulant-shape-incompatibility emitting SKIPPED rows instead of crashing.

## Done

### Track A — torch.compile on unroll_cell (Task 1)

- Added `unroll_cell(cell, x_seq, h0) -> h_seq` helper in `gru.py` that loops the cell over `T` steps and returns the stacked `(B, T, H)` hidden sequence.
- Rewrote `bench_gru.py`:
  - Imports `unroll_cell` from `gru.py`; removed the obsolete `run_cell` helper and the old `compile_cell` branch that wrapped the per-step cell (the anti-pattern).
  - New `--compile` flag additively enables a `compile_fwd_bwd_ms` column.
  - `_bench_compile` tries `mode="reduce-overhead"` first, falls back to `mode="default"` once, then records `compile_fail: <reason>` (reason ellipsized to ~50 chars) per combo — the sweep never aborts.
  - Uses `warmup=max(warmup, 5)` for compile measurements only (eager timings are untouched).
  - `torch._dynamo.config.suppress_errors = True` when `--compile` is set, keeping the bench alive on dicey graph breaks (the butterfly `torch.jit.script`-ed custom op is the main offender).
  - cuDNN rows print `-` in the compile column (cuDNN is already fused).

### Track B — structured B/C in LinearDiagRNN (Task 2)

- Extended `LinearDiagRNN.__init__` with `kind_B` and `kind_C` kwargs plus a `kind` shorthand that sets both. Both projections now route through `make_linear`. The `a` parameter stays dense `(H,)`.
- Rewrote `bench_lin_rnn.py`:
  - Replaced `--kind` with `--kinds` (comma-separated, symmetric) plus `--kind-B`/`--kind-C` (asymmetric).
  - Mutually exclusive → exit code 2 with a clear stderr error.
  - Table gains a `params` column; asymmetric mode adds `kind_B`/`kind_C` columns in place of the single `kind` column.
  - SKIPPED rows (e.g. `circulant` with non-pow2 H) place the reason string in the `naive_ms` cell and leave params/scan_ms/speedup blank; the sweep continues.
  - `--quick` defaults to `kinds="dense,butterfly"` so the stock sanity check exercises a structured kind without extra flags.

## Key Decisions

1. **Full-sequence return from unroll_cell.** Returning `torch.stack(outs, dim=1)` rather than just `h` is important for two independent reasons: (a) torch.compile needs a concrete tensor to trace and the `.sum().backward()` pattern needs a tensor that carries grad for all time-steps, and (b) it matches LinearDiagRNN's `forward_naive` return shape so we're benchmarking like-for-like.
2. **Compile on the whole unroll, not the cell.** reduce-overhead CUDA graphs only pay off when the recorded region is large. Wrapping the per-step cell (the pre-existing anti-pattern) records one tiny CUDA graph per step — no win possible. Wrapping `unroll_cell` records one graph that spans `T` steps.
3. **suppress_errors + fallback.** The combination of `torch._dynamo.config.suppress_errors = True` and the explicit reduce-overhead → default fallback is belt-and-suspenders: dynamo silently falls back to eager on graph breaks (no crash, no compile_fail), while Inductor-level hard failures surface as exceptions that the fallback can catch. The result: the sweep always produces a table, even when the structured custom op is hostile to dynamo.
4. **Fresh cell for compile measurement.** `_bench_compile` builds a new `StackedGateGRUCell` rather than reusing the eager one. This keeps the eager-vs-compiled comparison clean (no shared compiled graphs leaking between measurements) and avoids weird re-tracing edge cases.
5. **`a` stays dense.** Structuring `a` (which is already just a `(H,)` diagonal) would save nothing — it's already the minimal representation. Only the B (in→H) and C (H→out) projections, where structured matrices actually cut params, are routed through `make_linear`.
6. **SKIPPED cell placement.** Put the reason in `naive_ms` (the column after `params`) with params/scan_ms/speedup blank. This matches the pre-existing SKIPPED convention used in the old `bench_lin_rnn` and `bench_gru` scripts.
