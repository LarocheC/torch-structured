<objective>
Fix the TEST-04 perf gate `test_perf_gate_triton_at_60pct_cuda` in `tests/test_perf_grid.py`
so it computes the Triton-vs-CUDA ratio from the reliable `do_bench_p50_ms` column
(the `triton.testing.do_bench` measurement) instead of the inflated custom-harness
`wall_ms_p50` column.

Purpose: `wall_ms_p50` comes from the `measure_p50_p95` custom harness, which creates
two `torch.cuda.Event`s plus a full `torch.cuda.synchronize()` per iteration. At these
tiny kernel times (30-250 µs) it measures launch + sync + event overhead rather than
steady-state kernel time, running 47-91% (up to 7x) higher than `do_bench` for the same
kernel. The gate therefore reports implausible 7-11x ratios and false-fails ~10 cells.
TEST-04's requirement text itself says "measured via `triton.testing.do_bench`", so the
gate must read `do_bench_p50_ms`. Amends Phase 9 D-65b.

Output: a single-file edit to the gate logic and its docstrings. The harness's
`measure_p50_p95`, the baseline JSON, and `_routing.json` are NOT touched.
</objective>
